# Beam groups

For convenience, the [`BeamletOptics.AbstractBeamGroup`](@ref) offers a container-like interface for groups of [`Beam`](@ref)s as commonly used in other software packages. The following concrete implementations are currently provided:

```@repl
using BeamletOptics # hide
BeamletOptics.list_subtypes(BeamletOptics.AbstractBeamGroup);
```

Refer to the following sections for convenience constructors to generate the sources listed above.

!!! tip "Moving a beam group"
    Every beam group has a source position (`center`) and an [`orientation`](@ref) matrix, whose second column is the central source [`direction`](@ref) and whose first column is the sampling reference vector (`basis`). Both are updated when the group is moved. Refer to [`BeamletOptics.AbstractBeamGroup`](@ref) for the convention and to [Moving sources](@ref) for the kinematic API.

!!! info "Center ray"
    The first beam of every [`CollimatedSource`](@ref) and [`PointSource`](@ref) generated by one of the constructors below is the center ray: it starts at the source position along the central source direction. This does not apply to sources that wrap given beams.

## Collimated beam source

The collimated beam source is ideal to model light coming from a focal plane at infinity. This is useful for simulating plane wavefronts. You can define a collimated monochromatic [`Beam`](@ref) source as follows:

```@docs; canonical=false
CollimatedSource(::AbstractArray{<:Real}, ::AbstractArray{<:Real}, ::Real, ::Real)
```

![Collimated group of beams](collimated_beam_source.png)

Already existing beams, e.g. [`Beam`](@ref)s of [`PolarizedRay`](@ref)s as in the [Vectorial focusing at high NA](@ref) example, can be wrapped into a group with `CollimatedSource(beams, diameter, pos, dir)`. `PointSource(beams, NA, pos, dir)` and `AstigmaticBeamGroup(beams, pos, dir)` work analogously; instead of `dir`, a full `orientation` matrix can be passed.

A special constructor called [`UniformDiscSource`](@ref) is available, which offers an equal-area
sampling (Fibonacci pattern) and is thus favorable in situations where the weighting of the
individual beams becomes important, e.g. for calculating a point spread function using the [`intensity`](@ref) function.

```@docs; canonical=false
UniformDiscSource
```

![Collimated uniform group of beams](collimated_uniform_beam_source.png)

## Point beam source

The `PointSource` type is used to model emission from a spatially localized source that radiates [`Beam`](@ref)s in a range of directions. This is commonly used to simulate conical emission patterns, such as light emerging from a fiber tip or a light source for a lens objective with a known focal distance. You can specify the origin and a propagation direction, which are then used to construct the monochromatic `PointSource`.

```@docs; canonical=false
PointSource(::AbstractArray{<:Real}, ::AbstractArray{<:Real}, ::Real, ::Real)
```

Below you can find an exemplary illustration of a `PointSource`.

![Point source of beams](point_beam_source.png)

Analogous to [`UniformDiscSource`](@ref), a special constructor called [`UniformPointSource`](@ref)
is available, which samples the spherical cap around `dir` with an equal solid angle per ray
(Fibonacci/sunflower pattern), rather than in concentric rings. It returns a plain [`PointSource`](@ref).

```@docs; canonical=false
UniformPointSource
```

## Line and fan sources

For layout sketches, or to trace only one section of a system (e.g. the meridional plane), a two-dimensional source is often sufficient. The [`UniformLineSource`](@ref) is the two-dimensional counterpart of the collimated source: a plane sheet of parallel [`Beam`](@ref)s that start equidistantly on a line. It returns a plain [`CollimatedSource`](@ref).

```@docs; canonical=false
UniformLineSource
```

![Line source of beams](line_beam_source.png)

The [`UniformFanSource`](@ref) is the two-dimensional counterpart of the point source: a plane fan of [`Beam`](@ref)s from a single point with equidistant angles. It returns a plain [`PointSource`](@ref).

```@docs; canonical=false
UniformFanSource
```

![Fan source of beams](fan_beam_source.png)

Both sources include the marginal rays and should be used with an odd number of rays. The plane of the rays is spanned by `dir` and the `basis` keyword argument. The rays stay in this plane only if the system is symmetric with respect to it. Since the rays sample a line or a plane angle instead of an area or a solid angle, these sources are not suited for calculating a point spread function with the [`intensity`](@ref) function.

## Sampling and number of rays

A [`CollimatedSource`](@ref) or [`PointSource`](@ref) stores how its rays were sampled, such that [`num_rays!`](@ref) can regenerate them with another number of rays in the current pose of the source. How the beams are generated and how to add an own sampling is described in [Source sampling](@ref).

The catalog constructors above build their sampling and call the generic constructors, which take the sampling as an argument:

```@docs; canonical=false
CollimatedSource(::AbstractArray{<:Real}, ::AbstractArray{<:Real}, ::Real, ::BeamletOptics.AbstractSourceSampling, ::Real)
PointSource(::AbstractArray{<:Real}, ::AbstractArray{<:Real}, ::BeamletOptics.AbstractSourceSampling, ::Real)
```

## Astigmatic Beam Groups

For complex sources, the package provides the [`AstigmaticBeamGroup`](@ref) container. Several constructors are available for different scenarios:

- [`GaussianBeamletDecomposition`](@ref): Tiling a large Gaussian beam into many small stable beamlets.
- [`WavefrontBeamletDecomposition`](@ref): Importing an arbitrary complex scalar field (e.g. from a phase screen or camera data), or a vector field with an independent, spatially varying polarization (e.g. `OpticsBase`'s `PlaneField`, see [OpticsBase fields as beam groups](@ref)).
- [`CollimatedGaussianBeamletSource`](@ref): A square grid of parallel beamlets (ideal for aperture diffraction).
- [`SphericalGaussianBeamletSource`](@ref): A point-like source emitting a cone of beamlets (ideal for focused/divergent beams).
- [`EllipticalGaussianBeamletSource`](@ref): A point-like source emitting an elliptical cone of beamlets (ideal for sources with different fast/slow axis divergence).

A field that is close to one Gaussian mode and too small to be tiled into beamlets, e.g. the output of a single-mode fiber, is not turned into a group: [`GaussianModeDecomposition`](@ref) fits a single [`AstigmaticGaussianBeamlet`](@ref) to it.

The decompositions of a sampled field take the grid position as a positional argument, like every other source: `WavefrontBeamletDecomposition(x, y, amplitude, phase, pos, dir, λ)`, `WavefrontBeamletDecomposition(x, y, Eu, Ev, pos, dir, λ)` and `GaussianModeDecomposition(x, y, Eu, Ev, pos, dir, λ)`. The grid lies in the plane normal to `dir` through `pos`, and `pos` is the global position of the sample `x = y = 0`. For the two `WavefrontBeamletDecomposition` forms, `pos` is also the center of the returned group; the single beamlet of `GaussianModeDecomposition` starts at the centroid of the field on that plane.

### Beamlet sources and decompositions

The beamlet sources and decompositions normalize the beamlets such that their coherent superposition is the intended field. This section collects how.

**Gaussian beamlet decomposition.** The superposition of the beamlets of [`GaussianBeamletDecomposition`](@ref) is the sampled envelope convolved with a beamlet. For a Gaussian envelope of the waist ``w_\mathrm{env}`` it is a Gaussian of the waist ``\sqrt{w_\mathrm{env}^2 + w_{0s}^2}`` and the peak amplitude ``w_\mathrm{env}^2 / (w_\mathrm{env}^2 + w_{0s}^2)``, with the sub-waist ``w_{0s}`` of the beamlets. The envelope is therefore deconvolved, such that the superposition is the macroscopic beam of the waist `w0`, its peak amplitude and its power `P0`.

**Power of a tilted beamlet.** In [`WavefrontBeamletDecomposition`](@ref), each beamlet represents a cell of the area ``\Delta x \Delta y``. The footprint of a beamlet tilted by ``\theta`` against `dir` is stretched by ``1/\cos\theta`` on the sampling plane, so the Gaussian overlap integral there is ``\pi w_{0x} w_{0y} / \cos\theta``, and the field is scaled by ``\Delta x \Delta y \cos\theta / (\pi w_{0x} w_{0y})``.

**Local propagation direction and polarization of the vector field.** In the vector-field method of [`WavefrontBeamletDecomposition`](@ref), the local propagation direction at each grid point is found from the Eikonal equation, with the phase difference between neighboring samples taken from the complex vector overlap ``\mathbf{E}(a)^\mathsf{H} \mathbf{E}(b)``. This is continuous where the polarization changes and assumes that both components share one local wavevector, i.e. that the field is not the superposition of two waves with genuinely different directions at that point. The phase step between neighbors must stay below ``\pi``: a field tilted by ``\theta`` against `dir` needs ``\Delta x < \lambda / (2 \sin\theta)``, while the beamlets (waist `overlap * dx`) must stay much larger than ``\lambda``, so keep the sampling plane close to normal to the beam.

The `E0` of a beamlet keeps the given tangential components `Eu`, `Ev` and gets the normal component that makes it transverse to the local direction (``\mathbf{E} \cdot \mathbf{d} = 0``). Its amplitude is scaled by ``\cos\theta = \mathbf{d} \cdot \mathbf{dir}``, because the footprint of a tilted beamlet on the sampling plane is stretched by ``1/\cos\theta``. The sum of the beamlets then reproduces the sampled tangential field for oblique beams as well.

**Fit of the Gaussian mode decomposition.** [`GaussianModeDecomposition`](@ref) fits its beamlet in five steps:

1. Polarization: the dominant eigenvector of the coherence matrix ``\sum \mathbf{E} \mathbf{E}^\mathsf{H}``; the field is projected onto it.
2. Position and waist: centroid and principal axes of the second intensity moments; the beam radius along a principal axis is twice the rms width.
3. Direction: the mean transverse wave vector, from the intensity-weighted phase step between neighboring samples.
4. Curvature: the quadratic phase from the moments ``\langle r_i \partial_j \varphi \rangle`` of the phase gradient (phase steps between neighbors), taken along the principal axes of the intensity. Twist between curvature and intensity axes (general astigmatism) is not represented.
5. Amplitude and phase: the projection of the field onto the fitted mode.

**Coherent power of beamlet sources.** [`CollimatedGaussianBeamletSource`](@ref), [`SphericalGaussianBeamletSource`](@ref) and [`EllipticalGaussianBeamletSource`](@ref) emit beamlets of equal power that start in phase. Their profiles are Gaussians of the width ``w`` (the ``1/e^2`` half width of the intensity) about vectors ``\mathbf{v}_i`` in a common plane: the positions with the waist in the source plane of collimated beamlets, or the directions with the far-field divergence of beamlets from one point. Where the beamlets overlap, their fields add: two beamlets of the power ``P`` whose vectors differ by ``\delta`` contribute ``P \exp(-\delta^2 / (2 w^2))`` to the power of the superposition per pair, i.e. it carries ``P \sum_{ij} \exp(-|\mathbf{v}_i - \mathbf{v}_j|^2 / (2 w^2))`` instead of ``N P``. The fields of the beamlets are scaled such that the superposition carries the sum of their powers. This holds for all beamlets, also at the edge of the source, where fewer neighbors overlap.

### OpticsBase fields as beam groups

With `using OpticsBase`, a `PlaneField` handed over by another solver (e.g. the exit field of a fiber computed by a beam propagation method) becomes BMO beams again. [`WavefrontBeamletDecomposition`](@ref) tiles it into one beamlet per sample, which needs beamlets much larger than λ. [`GaussianModeDecomposition`](@ref) fits a single Gaussian beamlet instead, for small fields close to one Gaussian mode such as single-mode fiber output. Both take only the forward-travelling part of the field and require the plane to lie in vacuum or air. The detector side, `PlaneField(::Detector)`, is described under [OpticsBase interoperability](@ref).

Details of the `PlaneField` return path:

- The field used is `forward(f).E .* reference_phase(f)` in \[V/m\] peak amplitude, matching the units `AstigmaticGaussianBeamlet`'s `E0` expects. `forward(f)` is the stored array with the local-plane-wave forward/backward split applied, and `reference_phase(f)` the phase of the reference sphere (if any). The samples and the sphere are handed on separately (`R = f.R`), so the grid only has to resolve the phase of the stored array, not that of the sphere. For [`GaussianModeDecomposition`](@ref) the sphere likewise enters the fit analytically.
- Only the forward part is decomposed, because a `PlaneField` has no ready single propagation direction for its backward part, while the constructor needs one direction per call. A field without forward light (e.g. a purely backward wave, whose forward part is rounding noise) cannot be decomposed.
- `forward` splits each sample as a local plane wave along the reference direction. A beam at the angle ``\theta`` to it loses an amplitude of the order ``(1 - \cos\theta)/2``. Keep the plane close to normal to the beam, which the beamlet size requires anyway (see [`WavefrontBeamletDecomposition`](@ref)).
- `f` must lie in vacuum or air (`f.n == 1`): BMO starts beams in vacuum, and a field in a medium would need a medium-to-vacuum conversion of amplitude and optical path. An `ArgumentError` is thrown otherwise.
- Passing the result of `PlaneField(detector; ...)` back into [`WavefrontBeamletDecomposition`](@ref) and tracing the resulting beam group reproduces the original field (round trip), up to beamlet-grid discretization error.

```@docs
WavefrontBeamletDecomposition(::OpticsBase.PlaneField)
GaussianModeDecomposition(::OpticsBase.PlaneField)
```

## Solving a beam group

[`solve_system!`](@ref) traces a beam group by solving each of its beams, multithreaded, and the hits of all beams accumulate on the same [`Detector`](@ref)s. The internal steps are described in [Solving a beam group internally](@ref).
