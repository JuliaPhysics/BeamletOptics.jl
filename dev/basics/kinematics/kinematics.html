Kinematics ​

Optical elements, rays, beams and beam groups can move around freely in three-dimensional space, which enables the modeling of kinematics within optical setups, e.g. the alignment of a mirror or the displacement of a light source. All of them share one common kinematic API, which is explained on this page. Particularities of the individual entities are covered in the following sections.

  • Moving optical elements
    • Objects with multiple shapes
    • Groups of optical elements
  • Moving sources
    • Rays and beams
    • Beam groups

Optical system kinematics

Elements and sources can be moved freely between each call of solve_system!. However, during tracing it is assumed that all elements remain static.

Position, orientation and direction ​

Every movable entity has a position, represented as a -vector, which serves as its reference point for all movements. For optical elements, this is their self-defined center of gravity; for sources, it is the start of the light path. Entities with a full local coordinate system additionally have an orientation, represented by an orthonormal matrix in . If the entity is rotated, this matrix can be used to calculate the inverse transform into global coordinates. direction returns the local y-axis of such an entity, i.e. its optical axis, as orientation(x)[:, 2]. Rays and beams only have a direction, but no orientation.

Movement commands ​

The following movement commands are provided:

  • Translation

    • translate3d!

    • translate_to3d!

  • Rotation

    • rotate3d!

    • xrotate3d!

    • yrotate3d!

    • zrotate3d!

    • align3d!

  • Reset commands

    • reset_translation3d!

    • reset_rotation3d! (not available for rays and beams)

  • Pivot commands (groups only)

    • set_pivot3d!

Relative motion

Unless specified otherwise, the translation and rotation commands result in relative motions to the current position and orientation. This must be taken into account when trying to model a specific set of movements.

Rotations are performed about the position of the moved entity, unless a pivot is passed to rotate3d! explicitly. Angles are given in radians, and the axes of xrotate3d!, yrotate3d! and zrotate3d! are the global coordinate axes (see Conventions).

Static and movable entities ​

All optical elements, rays, beams and beam groups provided by BMO can be moved. A custom type can also be declared static, in which case every movement command throws an ArgumentError. How the kinematic API is implemented, and how a new element or beam type opts in or out of it, is explained in the Kinematic system section of the developer documentation.
